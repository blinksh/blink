Emoji Presentation Rendering Test

Validates that characters with Emoji=Yes / Emoji_Presentation=No render with text presentation (monochrome, single cell width) inside an x-screen element, while true emoji with the .emoji class retain emoji presentation.

Positive Tests — Text Presentation (should be monochrome, single-width)

These characters have Emoji=Yes but Emoji_Presentation=No. Without VS16, they must render in text presentation inside x-screen.

⏺ U+23FA BLACK CIRCLE FOR RECORD ⏸ U+23F8 DOUBLE VERTICAL BAR ⏹ U+23F9 BLACK SQUARE FOR STOP ⏏ U+23CF EJECT SYMBOL ⌨ U+2328 KEYBOARD ℹ U+2139 INFORMATION SOURCE ™ U+2122 TRADE MARK SIGN © U+00A9 COPYRIGHT SIGN ® U+00AE REGISTERED SIGN ♠ U+2660 BLACK SPADE SUIT ⌚ U+231A WATCH

Negative Tests — Emoji Presentation (should be colored, double-width)

These use the .emoji CSS class (as hterm applies to wcNode emoji), so they must retain emoji (colored) presentation.

⏺️ U+23FA + VS16 (explicit emoji) ❤️ U+2764 + VS16 HEAVY BLACK HEART 😀 U+1F600 GRINNING FACE 🚀 U+1F680 ROCKET

Negative Tests — CJK Characters (should remain double-width)

CJK characters use .wc-node (without .emoji). They must not be affected by the text-presentation rule.

中 U+4E2D 中 (CJK Unified) あ U+3042 あ (Hiragana) 가 U+AC00 가 (Hangul)
